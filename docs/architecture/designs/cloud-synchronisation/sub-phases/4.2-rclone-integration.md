## Deliverables

1. `RcloneTransport` struct implementing `CloudTransport` in `src-tauri/src/storage/cloud/rclone.rs`
2. Rclone bundled as Tauri sidecar binary in `tauri.conf.json` `externalBin` field (platform-specific paths for Windows, macOS, and Linux)
3. `run_rclone` function: construct subprocess via `tokio::process::Command`, pass args as `Vec<OsString>`, capture stdout/stderr, apply timeout via `tokio::time::timeout`
4. Remote path sanitisation — use the [Remote path sanitisation](../design.md#remote-path-sanitisation) rules from `design.md` (regex allowlist, reject `..`, reject leading `/`). Do not reproduce the regex here.
5. Stderr sanitisation — use the [Stderr sanitisation](../design.md#stderr-sanitisation) keyword list from `design.md`. Do not reproduce the list here.
6. Exit code mapping — use the [Exit code mapping](../design.md#exit-code-mapping) table from `design.md`. Do not reproduce values here.
7. `SyncConfig` struct with `max_concurrent` and `operation_timeout_seconds` — use the [Concurrency configuration](../design.md#concurrency-configuration) defaults from `design.md`. Do not reproduce values here.
8. Guided setup wizard functions:
   - `setup_s3_provider`: call `rclone config create` with access key ID, secret, bucket, region, endpoint
   - `setup_google_drive`: call `rclone config create` with OAuth flow, open browser via `tauri_plugin_opener` (Tauri 2 API)
9. Store non-sensitive `CloudEndpoint` fields (remote name, bucket, region, endpoint URL, `path_prefix`) in `cloud-config.json` in the Arx Runa app data directory — use the [Connection Descriptor](../design.md#connection-descriptor) paths from `design.md`. Do not reproduce platform paths here. Store Rclone credentials as an encrypted `rclone_config_blob` in the vault's SQLCipher database — see [Destination Session Storage](../design.md#destination-session-storage) in `design.md`.
10. At session open: decrypt `rclone_config_blob` from SQLCipher, write to a session-lived temp `rclone.conf`. Pass `--config <temp_path>` on every Rclone invocation. Overwrite and delete the temp file on session close.
11. Integration tests with local Rclone filesystem remote

## Validation Checkpoint

**Automated tests**:
```bash
cargo test storage::cloud::rclone
```
Must pass with integration tests using local filesystem remote.

**Manual verification**:
- Run setup wizard for S3-compatible provider (MinIO or Backblaze)
- Verify `cloud-config.json` created with non-sensitive endpoint fields (including `path_prefix`, no credentials)
- Verify `DestinationSession` row written to SQLCipher with encrypted `rclone_config_blob`
- Verify session-lived temp `rclone.conf` is written on session open and deleted on session close
- Upload a test blob via `RcloneTransport`
- Verify blob appears in cloud bucket with correct UUID name

**Security check**: 
- Subprocess invocation does not use shell interpolation; args are passed as separate OS strings
- Path traversal attempts (`../escape.txt`) are rejected
- Credentials never appear in logs, error messages, or command-line arguments (stderr sanitisation works; credentials passed via temp config file, not args)
- Session-lived temp `rclone.conf` is overwritten and deleted on session close

**Acceptance criteria**:
- `RcloneTransport` successfully uploads/downloads/deletes blobs to real cloud provider
- Path sanitisation blocks traversal attacks
- Credentials never appear in logs or error messages

## Implementation Notes

- Rclone binary must be downloaded from rclone.org and placed in `src-tauri/bin/` (platform-specific subdirectories)
- `tauri.conf.json` sidecar paths use `$RESOURCE` macro for portable builds
- On timeout, kill the Rclone process — see [Operation timeouts](../design.md#operation-timeouts) in `design.md` for the platform-specific kill mechanism
- OAuth flow requires `tauri_plugin_opener` to launch browser — test this manually (cannot be automated)
- `cloud-config.json` should be readable without authentication (needed for new-device recovery step 1)

## Implementation Decisions

- Kept Tauri shell capability least-privilege by removing `shell:default` and retaining only scoped `shell:allow-execute` for the `rclone` sidecar. **Rationale**: preserves sidecar execution while minimizing command execution surface. **Deferred follow-up**: none.
- Stored per-destination rclone configuration as a single validated stanza and exposed only `DestinationSessionPublic` outside internal storage persistence helpers. **Rationale**: prevents cross-destination credential bleed and avoids credential-bearing payloads in broader surfaces. **Deferred follow-up**: none.
- Enforced endpoint validation as HTTPS-by-default, with HTTP permitted only for explicit local-development loopback opt-in. **Rationale**: keeps bootstrap metadata non-sensitive while reducing plaintext transport risk. **Deferred follow-up**: monitor whether Phase 4.5 UX needs explicit insecure-endpoint guidance.
- Kept session `rclone.conf` lifecycle helpers explicit and awaitable, with integration ownership deferred to the planned session lifecycle wiring phase. **Rationale**: this sub-phase delivers storage/cloud primitives; full unlock/lock lifecycle orchestration is phase-sequenced. **Deferred follow-up**: wire coordinator ownership in Phase 4.5.
