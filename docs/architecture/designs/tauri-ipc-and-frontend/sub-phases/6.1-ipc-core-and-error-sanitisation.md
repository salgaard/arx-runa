## Deliverables

1. Module structure under `src-tauri/src/ui/`: `mod.rs`, `error.rs`, `auth_commands.rs`, `file_commands.rs`, `sync_commands.rs`, `destination_commands.rs`, `sharing_commands.rs`, `types.rs`
2. `IpcError` enum in `error.rs` with `#[serde(tag = "kind", content = "message")]` and `#[serde(rename_all = "camelCase")]`, using the canonical variant set from [Error Sanitisation](../design.md#error-sanitisation)
3. `From<auth::AuthenticationError> for IpcError` with explicit, sanitised mappings per [Error Sanitisation](../design.md#error-sanitisation); full internal details logged server-side only
4. `From<storage::StorageError> for IpcError` with explicit, sanitised mappings per [Error Sanitisation](../design.md#error-sanitisation)
5. `From<sync::SyncError> for IpcError` with explicit, sanitised mappings per [Error Sanitisation](../design.md#error-sanitisation)
6. Sanitisation rules enforced by the `From` impls: never expose sensitive internal filesystem paths, key material, memory addresses, stack traces, or specific crypto errors in any message string
7. All response types in `types.rs` aligned with [IPC Response Types](../design.md#ipc-response-types); do not duplicate struct contracts in this sub-phase doc
8. `AppState` struct in `mod.rs`: `database: Arc<RwLock<Option<DatabaseConnection>>>`, `cloud_transport: Arc<dyn CloudTransport>`, `device_monitor: Arc<dyn DeviceMonitor>`, `session_manager: Arc<SessionManager>`, `sync_status: Arc<RwLock<SyncStatus>>`
9. Input validation functions in `mod.rs` or a dedicated `validation.rs`: `validate_vault_path` (rejects path traversal `..`, absolute paths, and control characters), `validate_file_id` (UUID v4 format check), `validate_password` (non-empty check), `validate_chunk_size` (rejects values outside 131072–67108864; returns `IpcError::InvalidInput` with a message stating the allowed range)
10. Tauri command signatures are registered via `tauri::generate_handler![]` in `src-tauri/src/lib.rs` and must match the canonical full-profile command set in [Canonical Command Surface (Normative)](../design.md#canonical-command-surface-normative). For signature shapes, use [Command Signatures](../design.md#command-signatures). Note: `create_vault` accepts `chunk_size_bytes: u64` (validated by `validate_chunk_size`) and `epoch_buffer_enabled: bool` with hybrid-routing semantics defined in the Phase 3 design.
11. Build-time allowlist in `src-tauri/build.rs` includes the same canonical command set via `tauri_build::AppManifest::new().commands(&[...])` (no omissions, no extras) — see [Command Registration](../design.md#command-registration) in `design.md` for wiring shape.
12. `tauri.conf.json` has `withGlobalTauri: true` before Phase 6.2 starts (precondition for the Leptos WASM `invoke` wrapper); Phase 6.4 re-verifies this under CSP hardening.

## Validation Checkpoint

**Automated tests**:
```bash
cargo test ui::error
cargo test ui::validation
cargo build
```

`cargo test ui::error` must cover representative auth/storage/sync mappings from [Error Sanitisation](../design.md#error-sanitisation) and assert that sanitised IPC messages never include sensitive internals (paths, key material, stack traces, or raw hex key-like strings).

`cargo test ui::validation` must pass for:
- `validate_vault_path` rejects `../escape`, `/absolute/path`, `path\with\backslash`, and strings containing `\x00`–`\x1F`
- `validate_file_id` rejects malformed UUIDs and empty strings
- `validate_password` rejects empty strings
- `validate_chunk_size` rejects values below 131072 (128 KiB), above 67108864 (64 MiB), and zero

`cargo build` must succeed with all canonical Phase 6 commands registered (compile-time allowlist check).

**Acceptance criteria**:
- `IpcError` serialises correctly to `{"kind": "notFound", "message": "..."}` JSON shape
- All `From` impls log the full internal error before returning a sanitised message
- No internal error details (paths, addresses, crypto specifics) appear in any `IpcError` message

## Implementation Notes

- `IpcError` must implement `serde::Serialize` (not `Deserialize`) — it is only ever sent backend → frontend
- The `serde(tag = "kind", content = "message")` shape is required so the frontend `IpcError` struct can pattern-match on `kind` as a string discriminant
- Catch-all arms in `From` impls must use `tracing::error!` with `{:?}` (Debug format) to capture full context server-side, then return a fixed generic message — never interpolate the original error into the returned `IpcError`
- `AppState` fields use `Arc` so the state can be cloned across async command handlers; `RwLock` is used where shared mutable access is needed
- `validate_vault_path` should normalise the path and check the result does not escape a known root prefix — do not rely solely on the absence of `..` literals

---

## Security Review

**Required** — Invoke `security-reviewer` agent after implementation:
- Verify that every `From` impl arm produces a message free of sensitive internal filesystem paths, key material, memory addresses, stack traces, and specific crypto error details
- Verify that catch-all arms do not interpolate any portion of the original error into the returned message
- Verify that `validate_vault_path` blocks all traversal forms including URL-encoded variants and null bytes
