## Deliverables

1. Module structure under `src-tauri/src/ui/`: `mod.rs`, `error.rs`, `auth_commands.rs`, `file_commands.rs`, `sync_commands.rs`, `types.rs`
2. `IpcError` enum in `error.rs` with `#[serde(tag = "kind", content = "message")]` and `#[serde(rename_all = "camelCase")]`: variants `VaultLocked`, `AuthenticationFailed`, `NotFound`, `AlreadyExists`, `CloudError`, `InvalidInput`, `InternalError`
3. `From<auth::AuthError> for IpcError`: logs full error via `tracing::error!`, maps `InvalidPassword` and `KeyFileMismatch` → `AuthenticationFailed("Invalid credentials")`, `KeyFileNotFound` → `AuthenticationFailed("Key file not found")`, `SessionLocked` → `VaultLocked("Please unlock your vault")`, catch-all → `InternalError("An error occurred")`
4. `From<storage::StorageError> for IpcError`: logs full error, maps `FileNotFound` → `NotFound`, `DirectoryNotFound` → `NotFound`, `AlreadyExists` → `AlreadyExists`, catch-all → `InternalError`
5. `From<sync::SyncError> for IpcError`: logs full error, maps `NetworkUnavailable` → `CloudError("Network unavailable")`, `CloudProviderError` → `CloudError("Cloud provider error")`, catch-all → `InternalError`
6. Sanitisation rules enforced by the `From` impls: never expose file paths, key material, memory addresses, stack traces, or specific crypto errors in any message string
7. All response types in `types.rs`: `AuthResponse` (`vault_id: String`), `SessionStatus` (`is_unlocked: bool`, `timeout_seconds: u64`), `FileEntry` (`id: String`, `name: String`, `is_directory: bool`, `size: u64`, `modified: u64`), `ProgressUpdate` (`bytes_transferred: u64`, `total_bytes: u64`, `chunks_done: u32`, `total_chunks: u32`), `SyncProgressUpdate`, `SyncResult`, `SyncConflict`, `SyncStatus`
8. `AppState` struct in `mod.rs`: `database: Arc<RwLock<Option<DatabaseConnection>>>`, `cloud_transport: Arc<dyn CloudTransport>`, `device_monitor: Arc<dyn DeviceMonitor>`, `session_manager: Arc<SessionManager>`, `sync_status: Arc<RwLock<SyncStatus>>`
9. Input validation functions in `mod.rs` or a dedicated `validation.rs`: `validate_vault_path` (rejects path traversal `..`, absolute paths, and control characters), `validate_file_id` (UUID v4 format check), `validate_password` (non-empty check)
10. All 10 Tauri command signatures (`authenticate`, `lock_session`, `get_session_status`, `list_directory`, `upload_file`, `download_file`, `delete_file`, `sync_to_cloud`, `recover_from_cloud`, `get_sync_status`) registered via `tauri::generate_handler![]` in `src-tauri/src/lib.rs`
11. Build-time allowlist in `src-tauri/build.rs` listing all 10 command names via `tauri_build::AppManifest::new().commands(&[...])`

## Validation Checkpoint

**Automated tests**:
```bash
cargo test ui::error
cargo test ui::validation
cargo build
```

`cargo test ui::error` must pass for:
- `AuthError::InvalidPassword` maps to `IpcError::AuthenticationFailed` with message `"Invalid credentials"`
- `AuthError::KeyFileMismatch` maps to `IpcError::AuthenticationFailed` with message `"Invalid credentials"`
- `AuthError::SessionLocked` maps to `IpcError::VaultLocked`
- `StorageError::FileNotFound` maps to `IpcError::NotFound` with no path in message
- `StorageError::AlreadyExists` maps to `IpcError::AlreadyExists` with no path in message
- `SyncError::NetworkUnavailable` maps to `IpcError::CloudError`
- No message string contains `/`, `\`, `key`, `0x`, or a hex sequence of 32+ characters

`cargo test ui::validation` must pass for:
- `validate_vault_path` rejects `../escape`, `/absolute/path`, `path\with\backslash`, and strings containing `\x00`–`\x1F`
- `validate_file_id` rejects malformed UUIDs and empty strings
- `validate_password` rejects empty strings

`cargo build` must succeed with all 10 commands registered (compile-time allowlist check).

**Acceptance criteria**:
- `IpcError` serialises correctly to `{"kind": "notFound", "message": "..."}` JSON shape
- All `From` impls log the full internal error before returning a sanitised message
- No internal error details (paths, addresses, crypto specifics) appear in any `IpcError` message

## Implementation Notes

- `IpcError` must implement `serde::Serialize` (not `Deserialize`) — it is only ever sent backend → frontend
- The `serde(tag = "kind", content = "message")` shape is required so the frontend `IpcError` struct can pattern-match on `kind` as a string discriminant
- Catch-all arms in `From` impls must use `tracing::error!` with `{:?}` (Debug format) to capture full context server-side, then return a fixed generic message — never interpolate the original error into the returned `IpcError`
- `AppState` fields use `Arc` so the state can be cloned across async command handlers; `RwLock` is used where shared mutable access is needed
- `validate_vault_path` should normalise the path and check the result does not escape a known root prefix — do not rely solely on the absence of `..` literals

---

## Security Review

**Required** — Invoke `security-reviewer` agent after implementation:
- Verify that every `From` impl arm produces a message free of file paths, key material, memory addresses, stack traces, and specific crypto error details
- Verify that catch-all arms do not interpolate any portion of the original error into the returned message
- Verify that `validate_vault_path` blocks all traversal forms including URL-encoded variants and null bytes
