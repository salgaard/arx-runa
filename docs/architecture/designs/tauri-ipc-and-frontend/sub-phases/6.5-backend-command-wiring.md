**Parent roadmap**: [roadmap.md](roadmap.md)  
**Design sections**: [Canonical Command Surface (Normative)](../design.md#canonical-command-surface-normative), [IPC Commands](../design.md#ipc-commands), and [Backend Integration](../design.md#backend-integration) of [design.md](../design.md)

**Depends on**: [Phase 6.4](6.4-zero-trace-and-security-hardening.md) (security hardening must precede full backend wiring)

Phases 6.1–6.4 established the full IPC scaffolding and frontend surface. All
Tauri command handlers currently return `IpcError::InternalError("command not yet
wired")`. This phase connects each command to its Phase 2–5 backend implementation,
makes the end-to-end flows functional, and adds the remaining glue code that
was out of scope for the earlier sub-phases.

## Deliverables

1. Each Tauri command in `src-tauri/src/ui/` delegates to the corresponding
   Phase 2–5 entry point, returning the sanitised `IpcError` on failure.
2. `AppHandle::emit("device-event", payload)` emitted from the
   `DeviceMonitor` → `SessionManager` glue when a device is inserted or removed.
3. `tauri::ipc::Channel<ProgressUpdate>` accepted and driven from
   `vault_ops::upload_file` and `vault_ops::download_file`.
4. End-to-end manual verification passes: login → vault browser → upload →
   download → lock → re-login flow works against a real local vault.
