# Phase 2.1: USB Key File Format and DeviceMonitor

**Parent roadmap**: [roadmap.md](roadmap.md)  
**Design sections**: USB Key File (including Device monitoring), Trait Boundaries: KeySource and DeviceMonitor (lines 21-85, 462-501 of [design.md](../design.md))  
**Depends on**: Phase 1.3 (BLAKE3 checksum for key file fingerprinting)

---

## Deliverables

1. `KeySource` trait in `src-tauri/src/auth/mod.rs`: `fn read_key(&self) -> Result<Zeroizing<[u8; 32]>, KeySourceError>`
2. `KeySourceError` enum: `NotFound`, `InvalidSize { actual: usize }`, `ReadFailed(io::Error)`
3. `FileKeySource` struct implementing `KeySource` — reads from a filesystem path, validates file is exactly 32 bytes
4. `MockKeySource` struct implementing `KeySource` — returns caller-controlled bytes for testing without hardware
5. `DeviceMonitor` trait in `src-tauri/src/auth/mod.rs`: `fn watch(&self) -> Pin<Box<dyn Stream<Item = DeviceEvent> + Send>>` — the `Pin<Box<dyn …>>` return type keeps the trait dyn-safe so the OS-specific implementation can be selected at runtime; `impl Trait` (RPITIT) would make the trait non-dyn-safe
6. `DeviceEvent` enum: `Mounted { mount_path: PathBuf }`, `Unmounted { mount_path: PathBuf }`
7. `WindowsDeviceMonitor` implementing `DeviceMonitor` — WMI `Win32_VolumeChangeEvent` or `RegisterDeviceNotification` via the `windows` crate
8. `LinuxDeviceMonitor` implementing `DeviceMonitor` — `udev` crate, monitoring for block device add events with `SUBSYSTEM=block`
9. `MockDeviceMonitor` implementing `DeviceMonitor` — emits synthetic `DeviceEvent` values via an in-memory channel, controllable from test code without hardware
10. Auto-detection function: given a `mount_path` and a `key_file_blake3` reference hash, scan the mounted volume for files that are exactly 32 bytes, compute `blake3::hash(content)` for each, return the matching path or `None`
11. Local path hint: store last-used key file path in local config (not SQLCipher — must be readable before authentication); check remembered path first before triggering full-drive scan
12. Tests:
    - `FileKeySource` reads a valid 32-byte file successfully
    - `FileKeySource` returns `InvalidSize` when file is not 32 bytes
    - `FileKeySource` returns `NotFound` when file does not exist
    - `MockKeySource` returns controlled bytes
    - `MockDeviceMonitor` emits `Mounted` and `Unmounted` events in order
    - Auto-detection finds the matching key file among multiple 32-byte files
    - Auto-detection ignores files that are not 32 bytes
    - Auto-detection returns `None` when no file matches the reference hash

---

## Validation Checkpoint

**Automated tests**:
```bash
cargo test auth::key_source
cargo test auth::device_monitor
```
All tests must pass.

**Manual verification**:
- Insert a USB drive on the target platform
- Verify `WindowsDeviceMonitor` / `LinuxDeviceMonitor` emits a `Mounted` event with the correct `mount_path`
- Place a 32-byte file on the drive; verify auto-detection returns its path when given the correct BLAKE3 hash
- Place a file of a different size on the same drive; verify it is ignored

**Acceptance criteria**:
- `KeySource` trait and both implementations compile and pass all unit tests
- `DeviceMonitor` trait and all three implementations compile
- `MockDeviceMonitor` emits events controllably in tests (no hardware required)
- Auto-detection correctly identifies a matching 32-byte file and ignores non-matching files
- Local path hint is written and read without requiring SQLCipher to be open

## Implementation Notes

- `FileKeySource` must read the file into a `Zeroizing<[u8; 32]>` buffer — do not use a `Vec<u8>` intermediate that bypasses zeroization
- `MockKeySource` is test-only; gate it behind `#[cfg(test)]` or a `test-utils` feature flag to avoid shipping test code in release builds
- `LinuxDeviceMonitor` requires the `udev` crate; add it as an optional dependency gated on `target_os = "linux"`
- `WindowsDeviceMonitor` requires the `windows` crate with the appropriate feature flags for `Win32_System_Wmi` or `Win32_Devices_DeviceAndDriverInstallation`; gate on `target_os = "windows"`
- The 32-byte size filter on auto-detection is intentional and load-bearing — almost no legitimate files are exactly 32 bytes, making the scan near-instant on typical drives
- Local path hint file: `%APPDATA%/arx-runa/key-hint.json` (Windows) or `~/.local/share/arx-runa/key-hint.json` (Linux); no sensitive data, just a path string

---

## Security Review

**Not required** — this sub-phase performs no cryptographic operations beyond BLAKE3 hashing. BLAKE3 is used here solely as a preimage-resistant fingerprint comparator, not for key derivation. The key file content itself is only read into a `Zeroizing` buffer and passed to the KDF layer in Phase 2.2.
