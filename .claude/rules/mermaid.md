# Mermaid Diagrams — Rules

**Full syntax reference**: `.claude/reference/mermaid.md`

---

## Diagram Type → Use

| Type | Use for |
|------|---------|
| `flowchart TD` | Process flows, pipelines, key derivation trees |
| `sequenceDiagram` | IPC flows, auth flows, sync sequences |
| `erDiagram` | SQLCipher schema, manifest structure |
| `classDiagram` | Rust traits, type hierarchies |
| `stateDiagram-v2` | Session lifecycle, vault state machine |
| `graph TD` | Information flows, SSOT diagrams |

Stick to these six stable types. Experimental types (`architecture-beta`, `C4`, `timeline`) are documented in the reference but not used for core docs.

---

## Critical Syntax Constraints

**Flowchart node labels**
- Line breaks: `<br/>` — never `\n`
- Arrows: `#45;#62;` — never plain `->` or `-&gt;` (both cause empty squares in v11)
- Pipe char: `#124;` for `|`, `#124;#124;` for `||` — never literal (parsed as edge-label delimiter)
- Unicode / emoji: ASCII equivalents only — `>=` not `≥`, no emoji in labels
- Reserved word: never use `end` as a node ID; use `END` or `["end"]`
- Node IDs: never start with `o-` or `x-` (creates special edges)

**Flowchart edge labels**
- `-->|text|` only — never `-->|"quoted text"|` (quotes inside pipes confuse the lexer)

**Sequence diagram messages**
- Line breaks: `\n` — never `<br/>`
- Arrows in text: `#45;#62;` — never `->` or `-&gt;`
- Semicolons in text: `#59;` — never literal `;`
- Never nest `alt`/`end` inside `par`/`and`/`end` — flatten or inline condition in message text

**ER diagram attributes**
- FK arrows: `#45;#62;` — never `->` or `-&gt;`

---

## Layout & Readability

- Max 15 nodes per diagram — split on trust or layer boundaries if larger
- Use descriptive node IDs: `AUTH`, `E1`, `CRYPTO` — never `a`, `b`, `c`
- Label every edge meaningfully: `-->|derives|` not just `-->`
- Intermediate nodes must be explicit — never use an edge label as a substitute for a node
