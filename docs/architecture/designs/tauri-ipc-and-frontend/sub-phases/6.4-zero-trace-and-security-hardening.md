## Deliverables

1. CSP configuration in `tauri.conf.json` under `app.security.csp`:
   - `default-src 'self'`
   - `connect-src ipc: http://ipc.localhost`
   - `script-src 'self' 'wasm-unsafe-eval'`
   - `style-src 'self' 'unsafe-inline'`
   - `img-src 'self' asset: http://asset.localhost blob: data:`
   - No `localStorage`, `IndexedDB`, or service worker permissions (enforced at application level; verified by Zero-Trace audit)
2. `withGlobalTauri: true` set in `tauri.conf.json` (confirm present — required since Phase 6.2)
3. Clipboard capability explicitly denied in `tauri.conf.json` capabilities configuration
4. Verified state clearing on lock: after `lock_session` IPC completes, `SessionState` resets to defaults, `VaultActions::clear()` executes, and `SyncState` resets — confirmed by integration test inspecting signal values after lock
5. Verified password `zeroize` in `LoginPage`: audit that the password `String` is zeroed on both success and failure branches of the `authenticate` IPC call (introduced in Phase 6.3, confirmed here)
6. Exponential backoff on failed authentication in `SessionManager` (`src-tauri/src/auth/session_manager.rs`): 1 second base delay, doubles per attempt, 30 second maximum; backoff state stored in `SessionManager` in memory (resets on process restart)
7. No console logging of sensitive data: audit all `tracing` and `web_sys::console` call sites introduced in Phases 6.1–6.3 to confirm passwords, key material, and file contents are absent
8. Integration tests in `src-tauri/tests/` or `src/tests/`:
   - After lock: `localStorage` and `sessionStorage` are empty (inspected via `web_sys::window().local_storage()`)
   - After lock: `VaultState.files` is empty and `current_path` is reset
   - After lock: `SessionState.is_unlocked` is false and `vault_id` is `None`
   - After lock: password variable is zeroed (all bytes are zero)
   - Auth backoff: second failed attempt is delayed by at least 1 second; sixth attempt is capped at 30 seconds
9. Threat model documentation additions: compromised WebView scenario (CSP mitigations), clipboard exfiltration attack (denied capability), brute-force authentication (backoff defence)

## Validation Checkpoint

**Automated tests**:
```bash
cargo test ui::security
trunk build
```

`cargo test ui::security` must pass for:
- Auth backoff enforces delay between failed attempts
- State clearing removes all `VaultState` and `SessionState` fields
- Password bytes are zeroed after authentication attempt

**Manual verification**:
- Lock the vault via the UI lock button
- Open browser DevTools → Application → Storage: confirm `localStorage` and `sessionStorage` are empty
- Inspect the Leptos component tree: confirm no `FileEntry` data remains in any signal
- Attempt authentication with a wrong password repeatedly; observe each retry is delayed (visible in network tab or logs)

**Acceptance criteria**:
- CSP is present in `tauri.conf.json` with all required directives
- Clipboard capability is denied
- All Zero-Trace integration tests pass
- Auth backoff test confirms delays at 1s, 2s, 4s, 8s, 16s, 30s (capped)
- `cargo test` and `trunk build` both succeed with no warnings

## Implementation Notes

- The CSP `style-src 'unsafe-inline'` allowance is required by Tailwind's JIT mode which injects inline styles; this is an accepted trade-off documented in the threat model
- Auth backoff must be applied in the backend `SessionManager`, not the frontend — the frontend could be bypassed by a direct IPC call
- `zeroize` on a Rust `String` requires converting to `Vec<u8>`, zeroing, and dropping; or using the `zeroize` crate's `Zeroize` impl for `String` directly (available in `zeroize >= 1.3`)
- The `withGlobalTauri: true` setting exposes `window.__TAURI__` globally; the CSP `script-src 'self'` ensures only same-origin scripts can access it
- The absence of `localStorage` use is an application-level guarantee — there is no browser security mechanism that prevents JavaScript from calling `localStorage.setItem`. The Zero-Trace audit (integration test) checks that no code path actually writes to it

## Security Review

**Required** — Invoke `security-reviewer` agent after implementation:
- Zero-Trace verification: confirm no `localStorage`, `sessionStorage`, `IndexedDB`, or `document.cookie` writes in the WASM bundle
- CSP completeness: confirm all directives are present and no overly permissive sources are included
- Brute-force protection: confirm backoff is applied server-side and cannot be bypassed via concurrent requests or process restart
- Password zeroization: confirm zeroing occurs on both success and failure branches
