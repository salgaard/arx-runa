## Deliverables

1. `encrypt_chunk(plaintext: Vec<u8>, file_key: &FileKey, file_id: &FileId, chunk_index: ChunkIndex) -> Vec<u8>` in `src-tauri/src/crypto/encrypt_chunk.rs` — produces wire-format blob `[24-byte nonce | ciphertext | 16-byte Poly1305 tag]`
2. `decrypt_chunk(blob: VerifiedBlob, file_key: &FileKey, file_id: &FileId, chunk_index: ChunkIndex) -> Result<Vec<u8>, CryptoError>` in `src-tauri/src/crypto/decrypt_chunk.rs` — accepts `VerifiedBlob` (defined in Phase 1.3 `checksum.rs`) to enforce check-before-decrypt at the type level
3. AAD construction: `file_id (16 bytes) || chunk_index (4 bytes, big-endian u32)` — 20 bytes total; used in both encrypt and decrypt
4. Wire format parsing in `decrypt_chunk`: extract nonce (bytes `0..24`), tag (last 16 bytes), ciphertext (bytes `24..len-16`); return `CryptoError::InvalidBlobFormat` if `blob.len() < 40`
5. Both functions use `encrypt_in_place_detached()` / `decrypt_in_place_detached()` from the `chacha20poly1305` crate for explicit control over tag placement
6. Unit tests: `test_encrypt_decrypt_round_trip`, `test_decrypt_wrong_file_id_fails`, `test_decrypt_wrong_chunk_index_fails`, `test_decrypt_wrong_key_fails`, `test_decrypt_corrupted_ciphertext_fails`, `test_decrypt_corrupted_tag_fails`, `test_decrypt_truncated_blob_fails`
7. Property-based tests: `prop_encrypt_decrypt_identity` (arbitrary plaintext round-trips), `prop_different_nonces` (two encryptions of the same plaintext produce different ciphertexts)

---

## Validation Checkpoint

**Automated tests**:
```bash
cargo test crypto::encrypt_chunk
cargo test crypto::decrypt_chunk
```
All tests must pass.

**Acceptance criteria**:
- Round-trip: `decrypt_chunk(encrypt_chunk(plaintext, ...), ...)` returns original plaintext for all inputs
- Wrong `file_id` → `CryptoError::DecryptionFailed` (not panic, not incorrect plaintext)
- Wrong `chunk_index` → `CryptoError::DecryptionFailed`
- Wrong key → `CryptoError::DecryptionFailed`
- Single-byte ciphertext corruption → `CryptoError::DecryptionFailed`
- Single-byte tag corruption → `CryptoError::DecryptionFailed`
- Blob shorter than 40 bytes → `CryptoError::InvalidBlobFormat`
- Two encryptions of identical plaintext produce blobs with different nonces (property test)

**Manual verification**: None required for this sub-phase.

## Implementation Notes

- Import `XChaCha20Poly1305` from the `chacha20poly1305` crate; do not use `ChaCha20Poly1305` — the 96-bit nonce variant is rejected by design.
- Call `generate_nonce()` from Phase 1.1 for every encryption; never reuse or derive nonces.
- The tag is appended after the ciphertext by `encrypt_in_place_detached` — assemble the final blob as `nonce || ciphertext_buffer || tag`.
- For `decrypt_in_place_detached`, the ciphertext buffer must be mutable; copy `blob[24..len-16]` into a `Vec<u8>` before passing.
- `encrypt_chunk` takes `plaintext: Vec<u8>` by value to allow in-place mutation without an extra allocation.
- Empty plaintext (`Vec::new()`) is a valid input — the ciphertext will be 40 bytes (nonce + tag only); tests should cover this case.
- Add `proptest` to `[dev-dependencies]` in `Cargo.toml` before writing property-based tests.

## Security Review

**Required** — Invoke `security-reviewer` agent after implementation:
- AAD binding: confirm `file_id || chunk_index` is included in every AEAD call with no possibility of omission
- Nonce source: confirm `generate_nonce` (CSPRNG) is the sole nonce source; no sequential fallback exists
- Wire format: confirm tag is always verified before plaintext is returned (no partial decryption leaks)
