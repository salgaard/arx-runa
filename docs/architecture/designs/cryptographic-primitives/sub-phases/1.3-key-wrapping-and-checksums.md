## Deliverables

1. `generate_file_key() -> FileKey` in `src-tauri/src/crypto/generate_file_key.rs` — uses `rand::rng().random::<[u8; 32]>()` (rand 0.10 API; `gen` is a reserved keyword in Rust 2024)
2. `wrap_file_key(file_key: &FileKey, key_encryption_key: &KeyEncryptionKey) -> WrappedFileKey` in `src-tauri/src/crypto/wrap_key.rs` — XChaCha20-Poly1305 with random 24-byte nonce, empty AAD, wire format `[24-byte nonce | 32-byte encrypted key | 16-byte tag]` = 72 bytes total
3. `unwrap_file_key(wrapped: &WrappedFileKey, key_encryption_key: &KeyEncryptionKey) -> Result<FileKey, CryptoError>` in `src-tauri/src/crypto/wrap_key.rs` — returns `CryptoError::DecryptionFailed` on authentication failure
4. `compute_checksum(encrypted_blob: &[u8]) -> Blake3Hash` in `src-tauri/src/crypto/checksum.rs` — uses the `blake3` crate; operates on the encrypted blob, not plaintext
5. `VerifiedBlob(Vec<u8>)` opaque newtype in `src-tauri/src/crypto/checksum.rs` — only constructible via `verify_checksum`; passed to `decrypt_chunk` to enforce check-before-decrypt at compile time
6. `verify_checksum(blob: Vec<u8>, expected: &Blake3Hash) -> Result<VerifiedBlob, CryptoError>` in `src-tauri/src/crypto/checksum.rs` — returns `CryptoError::ChecksumMismatch` on mismatch; consumes the blob to produce an authenticated `VerifiedBlob`
7. Update `decrypt_chunk` signature (in `src-tauri/src/crypto/decrypt_chunk.rs`) to accept `VerifiedBlob` instead of `&[u8]` — this finalises Phase 1.2's API
8. Tests: `test_wrap_unwrap_file_key_round_trip`, `test_unwrap_wrong_kek_fails`, `test_checksum_detects_corruption`, `prop_checksum_deterministic` (same input always yields same hash), `test_generate_file_key_not_all_zeros`, `test_verify_checksum_rejects_tampered_blob`

## Validation Checkpoint

**Automated tests**:
```bash
cargo test crypto::wrap_key
cargo test crypto::checksum
cargo test crypto::generate_file_key
```
All tests must pass.

**Acceptance criteria**:
- `unwrap_file_key(wrap_file_key(key, kek), kek)` returns the original key bytes
- Wrong `KeyEncryptionKey` → `CryptoError::DecryptionFailed`
- `compute_checksum` is deterministic: identical blobs produce identical `Blake3Hash`
- Single-byte mutation of an encrypted blob produces a different `Blake3Hash`
- `verify_checksum` returns `Err` when the blob has been tampered with
- `VerifiedBlob` is only constructible via `verify_checksum` — `decrypt_chunk` cannot be called with a raw `Vec<u8>`
- `generate_file_key` does not return an all-zero key (probabilistic sanity check)
- Two consecutive calls to `generate_file_key` produce distinct keys

**Manual verification**: None required for this sub-phase.

## Implementation Notes

- Key wrapping uses **empty AAD** (`&[]`) — the `WrappedFileKey` blob is self-contained and carries its own nonce and tag; no external context binding is required for wrapping.
- The unwrapped `FileKey` must be constructed inside `SecretBox<[u8; 32]>` immediately; do not hold the raw bytes in a local variable longer than necessary.
- `Blake3Hash` is computed over the ciphertext blob (post-encryption), not over plaintext. This enables integrity checking before decryption — detect tampering without decrypting.
- `VerifiedBlob` is defined in `checksum.rs` and imported by `decrypt_chunk.rs`. Phase 1.3 finalises the `decrypt_chunk` signature that Phase 1.2 stubbed with a `todo!()` or `blob: Vec<u8>` placeholder — update the signature and all tests in `decrypt_chunk.rs` to accept `VerifiedBlob` as part of this phase.
- `compute_checksum` must not allocate a copy of the blob; use `blake3::hash(encrypted_blob)` directly.
- Add `blake3` to `[dependencies]` in `Cargo.toml` before implementation.
- The `prop_checksum_deterministic` property test is straightforward: `compute_checksum(input) == compute_checksum(input)` for arbitrary byte vectors.

## Security Review

**Required** — Invoke `security-reviewer` agent after implementation:
- Key wrapping: confirm nonce is fresh for every wrap call; confirm tag verification occurs in `unwrap_file_key` before raw bytes are exposed
- Zeroization: confirm the intermediate `[u8; 32]` buffer in `unwrap_file_key` is zeroed after `FileKey` construction
- BLAKE3 scope: confirm checksum is only ever computed over ciphertext, never over plaintext (guards against accidental misuse)
