## Deliverables

1. `LoginPage` component in `src/auth/login_page.rs`: password `<input type="password">`, `KeyFileIndicator` sub-component, error display, submit button that calls `authenticate` IPC, password string zeroed via `zeroize` immediately after the IPC call completes
2. `KeyFileIndicator` component: auto-detects key file path from `DeviceMonitor` events and displays the detected path; falls back to a manual file selection button when no device is detected
3. `VaultCreationPage` component in `src/auth/vault_creation_page.rs`: vault name input, password input, tier selector (Tier 1 / Tier 2), optional key file destination picker (shown for Tier 2 only), cloud endpoint fields, chunk size control (preset picker with Standard 4 MiB / Documents 512 KiB / Media 16 MiB / Paranoid 64 MiB plus a free-entry field clamped to 128 KiB–64 MiB), epoch buffer toggle with hybrid-routing explanation ("Opt-in: files smaller than chunk size are packed before upload; larger files upload immediately"), submit button that calls `create_vault` IPC; password zeroed immediately after the call
4. `VaultBrowser` component in `src/vault/vault_browser.rs`: `Breadcrumbs`, `FileList`, `DropZone`, `UploadButton`, loading spinner, and error display; reads state from `use_session()` and `use_vault_actions()`
5. `DropZone` component in `src/vault/drop_zone.rs`: full-area drag-and-drop target that calls `upload_file` IPC for each dropped path; idle state shows "Drag files here"; drag-over state highlights border; processing state shows queued file count and spinner; `UploadButton` remains as fallback
6. `FileList` component rendering a list of `FileItem` entries; each `FileItem` shows type icon, name, size, and modified date
7. `Breadcrumbs` component rendering the `current_path` as clickable path segments, each calling `VaultActions::navigate`
8. `UploadButton` component triggering a native file picker and calling the `upload_file` IPC command
9. `ProgressModal` component in `src/transfer/progress_modal.rs` displaying real-time transfer progress from `tauri::ipc::Channel<ProgressUpdate>`; shows bytes transferred, total bytes, and a progress bar
10. `AppShell` layout component in `src/layout/app_shell.rs`: header with application logo and `SessionStatus` display
11. `SessionStatus` component: shows remaining session timeout countdown and a lock button that calls `lock_session` IPC then `VaultActions::clear()`
12. Generic components in `src/components/`: `Button`, `Input`, `Modal`, `Spinner`
13. Leptos routing in `src/main.rs`: renders `LoginPage` when `SessionState.is_unlocked` is false and no vault creation is in progress; renders `VaultCreationPage` when the user initiates new vault creation; renders `VaultBrowser` wrapped in `AppShell` when the vault is unlocked
14. Tailwind CSS v4 styling using brand tokens (`bg-iron`, `text-bone`, and related custom tokens defined in the `@theme {}` block in `input.css`)

## Validation Checkpoint

**Automated tests**:
```bash
trunk build
```

Component tests (where Leptos testing infrastructure supports):
- `Breadcrumbs` renders one segment per path component
- `SessionStatus` lock button triggers `VaultActions::clear()` and navigates to login view

**Manual verification**:
- Open the application, initiate vault creation; verify `VaultCreationPage` renders with chunk size presets and epoch buffer toggle
- Complete vault creation with Standard chunk size and epoch buffer off; verify navigation to `LoginPage`
- Enter credentials and a key file; verify navigation to `VaultBrowser`
- Drag a file onto the `DropZone`; verify drag-over highlight appears and `ProgressModal` opens on drop
- Navigate into a directory via `Breadcrumbs`; verify `FileList` updates and path segment is added
- Initiate an upload via `UploadButton`; verify `ProgressModal` appears and updates in real time
- Click the lock button in `SessionStatus`; verify the UI returns to `LoginPage` and no file data is visible

**Acceptance criteria**:
- `trunk build` completes without errors
- `VaultCreationPage` submits `chunk_size_bytes` and `epoch_buffer_enabled` to `create_vault` IPC
- `chunk_size_bytes` free-entry field clamps to 131072–67108864 before submission
- Epoch buffer toggle copy and behavior match the hybrid routing contract (small files packed when enabled; large files remain immediate)
- The login → vault browser navigation flow works end to end with a running backend
- `ProgressModal` receives and renders at least one `ProgressUpdate` event during an upload

## Implementation Notes

- The password `zeroize` call must happen inside the `authenticate` handler regardless of whether the IPC call succeeds or fails — use a `defer`-style pattern or explicit cleanup on both branches
- `tauri::ipc::Channel<ProgressUpdate>` is passed from the frontend as an IPC argument; the channel is created in the WASM layer via the Tauri JS API before calling `invoke_command`
- Tailwind v4 brand token classes (e.g., `bg-iron`, `text-bone`) are defined in the `@theme {}` block in `input.css`; Tailwind v4 auto-generates utility classes from these CSS custom properties — no `tailwind.config.js` is used
- `DeviceMonitor` events for `KeyFileIndicator` arrive as Tauri events (not commands); use `tauri::event::listen` in the WASM layer to subscribe
- `Modal` component should render into a portal at the document root to avoid z-index conflicts with the `AppShell` layout

## Implementation Decisions

| Decision | Alternatives considered | Rationale |
|---|---|---|
| Flat file layout (`src/auth.rs`, `src/vault.rs`, `src/transfer.rs`, `src/layout.rs`, `src/components.rs`) instead of subdirectories | Sub-directory per feature (`src/auth/login_page.rs`, …) | Tooling limitation during implementation; flat layout delivers the full component surface within the ~400-LoC budget. Refactor to subdirectories deferred to a later sub-phase. |
| Conditional `Show` / `RwSignal<bool>` routing instead of `leptos_router` | URL-based routing with `leptos_router` | Session-state transitions are not URL-driven; conditional render is minimal and avoids routing overhead within the 400-LoC budget. |
| `Arc<Mutex<Option<js_sys::Function>>>` for the Tauri event unlisten handle in `KeyFileIndicator` | `Rc<RefCell<…>>` (fails `on_cleanup: Send + Sync`), `forget()` only (leaks unlisten) | `on_cleanup` in Leptos 0.8 requires `Send + Sync + 'static`. `js_sys::Function` carries `unsafe impl Send + Sync` from wasm-bindgen. `Arc<Mutex<…>>` satisfies the bound while ensuring `unlisten()` is called on component unmount. The `Closure` is `forget()`-ed — Tauri holds the JS reference; once `unlisten()` fires, Tauri drops its reference and the JS GC reclaims the closure. |
| `VaultActions::set_error(self, message: String)` helper added to vault context | Inline `vault_actions.error.set(Some(…))` at call sites | Encapsulates signal mutation in one place; reduces call-site boilerplate in `DropZone` and `UploadButton`. |
| `validate_vault_creation_form` pure function for `VaultCreationPage` validation | Inline validation in the submit handler | Enables host-target unit tests without WASM runtime; five tests added covering the six error paths. |
| `join_vault_path(current: &str, name: &str) -> String` pure helper in `vault.rs` | String formatting inline in `FileItem` | Three unit tests verify root, nested, and trailing-slash cases; isolates the path-join logic from the component. |
| Acceptance scope narrowed: `trunk build` + unit tests; end-to-end flows deferred to Phase 7 | Blocking on full manual verification | All IPC commands return `InternalError("command not yet wired")` until Phase 7 wires backend orchestration. Narrowing is documented in plan Concern 3. |
| Backend `DeviceMonitor → AppHandle::emit("device-event")` bridge deferred to Phase 7 | Wire bridge in Phase 6.3 | Bridge requires `src-tauri/src/auth/` edits outside 6.3 scope; subscriber shape is proved and tolerates zero emissions in 6.3. |
| In-App File Viewer deferred | Implement viewer in 6.3 | Not in enumerated sub-phase deliverables; `get_file_content` remains reachable but has no consumer until a later sub-phase. |
