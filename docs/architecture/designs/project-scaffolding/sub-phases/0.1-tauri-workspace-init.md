## Deliverables

1. Run `cargo create-tauri-app . --template leptos --identifier com.arxruna.app --app-name "Arx Runa" --manager cargo` in the repo root to generate `src-tauri/` containing: `Cargo.toml`, `tauri.conf.json`, `capabilities/`, `icons/`, `build.rs`, `src/main.rs`, `src/lib.rs`
2. Replace the root `Cargo.toml` bare-binary content with a **package+workspace manifest** following the `create-tauri-app` Leptos template convention (see [Workspace Layout rationale in `design.md`](../design.md#workspace-layout) for why this pattern over a virtual manifest). Keep the template-generated frontend target declaration (`[[bin]]` for current output; `[lib]` if a future template changes):
   ```toml
   [workspace]
   members = ["src-tauri"]
   resolver = "3"

   [package]
   name = "arx-runa"
   version = "0.1.0"
   edition = "2024"

   # Keep exactly one target declaration from the template output.
   [[bin]]
   name = "arx-runa"
   path = "src/main.rs"
   ```
   Then add the `[dependencies]` block using the **Frontend dependencies table** from [`design.md`](../design.md#frontend-src--compiled-by-trunk). Use the exact crate versions and features listed there — do not reproduce the list here.
3. Update the generated `src-tauri/Cargo.toml` edition to `2024` if the template does not set it
4. Immediately update the generated Leptos dependency to the version in the [Technology Versions table of `design.md`](../design.md#technology-versions) (templates generate `"0.6"`) before first compilation
5. Replace the old bare-binary `src/main.rs` with the template Leptos frontend entrypoint (this may be an overwrite rather than a deletion). The `src/` directory remains for the Leptos frontend
6. Set `tauri.conf.json` key values using the [Tauri Configuration table in `design.md`](../design.md#tauriconfjson-key-settings)
7. Verify `cargo build` succeeds on the generated skeleton

## Validation Checkpoint

**Automated**:
```bash
cargo build
```
Must compile without errors.

**Manual verification**:
- `cargo metadata --no-deps | jq '.workspace_members'` — must include `src-tauri` (root frontend package may also appear for package+workspace manifests)
- Root `Cargo.toml` keeps exactly one frontend target declaration (`[[bin]]` for the current template output); no orphan target points to a removed hello-world stub
- `src/main.rs` is the template Leptos entrypoint (the previous bare hello-world file is replaced)

**Acceptance criteria**:
- `cargo build` exits 0
- Workspace membership includes `src-tauri`
- `tauri.conf.json` has the correct identifier and product name

## Implementation Notes

- `cargo create-tauri-app` is interactive by default. Use flags to skip prompts:
  ```bash
  cargo create-tauri-app . --template leptos --identifier com.arxruna.app --app-name "Arx Runa" --manager cargo
  ```
  The `.` target generates into the current directory — review which files it overwrites (particularly `Cargo.toml` and any existing `src/` content). If the generator refuses a non-empty directory, use `--force` or scaffold to a temporary directory and copy files in.
- If the template generates a `package.json` at the root (for Tailwind), keep it — it's needed for Phase 0.3.
- The template may generate `src/app.rs` alongside `src/main.rs`. Keep `src/app.rs` — it becomes the root Leptos component. Only remove the bare-binary `src/main.rs` if separate from the Leptos entry point.
- Edition 2024 with resolver 3 is set in the workspace root `Cargo.toml`. Individual crate `Cargo.toml` files inherit the resolver from the workspace.
