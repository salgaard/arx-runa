# Phase 4.3: Vault Header Upload and Download

**Parent roadmap**: [roadmap.md](roadmap.md)  
**Design sections**: Vault Header Structure, Upload Flow, Download and Parse Flow, Security Analysis (lines 367-459 of [design.md](../design.md))  
**Depends on**: [Phase 4.2](4.2-rclone-integration.md) (RcloneTransport)

---

## Deliverables

1. `VaultHeader` struct in `src-tauri/src/storage/cloud/vault_header.rs` with fields: `vault_id`, `schema_version`, `tier`, `argon2_salt`, `argon2_params`, `key_file_blake3`
2. `Argon2Params` struct with `memory_cost`, `time_cost`, `parallelism` fields
3. `upload_vault_header` function: serialize `VaultHeader` to JSON → write to temp file → `upload_blob(temp_path, "vault-header.json")` → delete temp
4. `download_vault_header` function: `download_blob("vault-header.json", temp_path)` → read and deserialize → validate schema version, salt length, Argon2 params → delete temp
5. Validation logic — use the [Download and parse flow](../design.md#download-and-parse-flow) from `design.md`. Key rules: `schema_version` is supported; `tier` is 1 or 2; `argon2_salt` decodes to 32 bytes; `argon2_params` meet minimums; `key_file_blake3` is required (32-byte hex) for tier 2 and must be `null` for tier 1. Do not reproduce the full validation sequence here — consult `design.md` during implementation.
6. Tests: Upload → download round-trip, validation rejects malformed headers

---

## Validation Checkpoint

**Automated tests**:
```bash
cargo test storage::cloud::vault_header
```

**Manual verification**:
- Upload vault header to real cloud provider
- Download from cloud and verify JSON parses correctly
- Inspect `vault-header.json` in cloud bucket — confirm it's plaintext JSON

**Acceptance criteria**:
- Vault header uploads as plaintext JSON
- New-device recovery flow can download and parse vault header before authentication
- Validation correctly rejects malformed headers

## Estimated Scope

- **Production code**: ~120 lines (struct + serialize + validate)
- **Test code**: ~80 lines

## Implementation Notes

- Use `serde_json` for serialization/deserialization
- Base64 encoding: use `base64` crate with standard alphabet
- Hex encoding: use `hex` crate for `key_file_blake3`
- Temp files should be written to Arx Runa staging directory (from Phase 3), not system temp
- Vault header is intentionally plaintext — do not encrypt (needed for bootstrap)
