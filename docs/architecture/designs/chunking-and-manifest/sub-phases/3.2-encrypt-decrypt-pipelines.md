## Deliverables

1. `encrypt_file(source: &Path, file_id: Uuid, file_key: &FileKey, chunk_size: usize, staging_directory: &Path) -> Result<Vec<ChunkRecord>, StorageError>` in `src-tauri/src/storage/pipeline.rs` — streaming via `BufReader`, zero-pad each chunk to `chunk_size`, encrypt via `encrypt_chunk`, compute BLAKE3 checksum over the encrypted wire blob, write to staging as `<uuid>.blob` via `BufWriter`, zeroize plaintext buffer after each chunk
2. `decrypt_file(destination: &Path, file_id: Uuid, file_key: &FileKey, file_size: u64, chunks: &[ChunkRecord], blob_directory: &Path) -> Result<(), StorageError>` — read wire blob, verify BLAKE3 before any decryption attempt, decrypt via `decrypt_chunk`, truncate last chunk to `file_size - (chunk_count - 1) * chunk_size` bytes, zeroize plaintext buffer after each chunk
3. File key lifecycle integration in `src-tauri/src/storage/vault_ops.rs`: generate `file_key` (random 256-bit via CSPRNG) → wrap with `key_encryption_key` → begin SQLCipher transaction → insert node row → encrypt all chunks → insert chunk rows → commit → zeroize `file_key`
4. File access flow: unwrap `file_key` from `nodes` table → decrypt chunks in `chunk_index` order → zeroize `file_key` on completion or error
5. Streaming invariant enforcement: at no point is more than one chunk's plaintext in memory; verified by test
6. Test suite covering: chunk boundary cases (0 bytes, 1 byte, `chunk_size - 1`, `chunk_size`, `chunk_size + 1`, exact multiples, multi-chunk files), BLAKE3 mismatch rejection (error returned before `decrypt_chunk` is called), UUID v4 blob naming (blob files in staging are named `<uuid>.blob`), full file round-trip (encrypt then decrypt produces byte-identical output), 0-byte file (no chunks produced, no staging files created)
7. Property-based tests using `proptest`: arbitrary file sizes (0 to 20 MiB) round-trip correctly through encrypt/decrypt

---

## Validation Checkpoint

**Automated tests**:
```bash
cargo test storage::pipeline
```
All tests including property-based tests must pass.

**Manual verification**:
- Encrypt a multi-chunk file (e.g., 10 MiB); inspect the staging directory — confirm blob count matches `ceil(10 MiB / chunk_size_bytes)`, each file is exactly `chunk_size_bytes + 40 bytes` (chunk payload + 24-byte nonce + 16-byte Poly1305 tag)
- Corrupt one byte in a staging blob; attempt decrypt — confirm `StorageError::ChecksumMismatch` is returned

**Acceptance criteria**:
- All chunk boundary test cases pass
- BLAKE3 mismatch is detected and returned as an error before any decryption is attempted
- After `encrypt_file` returns, no plaintext chunk buffer remains in heap memory (zeroize called)
- After `decrypt_file` returns (success or error), no plaintext chunk buffer remains in heap memory
- 0-byte file: `encrypt_file` returns `Ok(vec![])` with no staging files created

## Implementation Notes

- AAD construction per the crypto design: `file_id` (16 bytes, UUID as bytes) `||` `chunk_index` (u32, big-endian, 4 bytes). This must match the construction in `encrypt_chunk`/`decrypt_chunk` exactly — mismatched AAD causes AEAD authentication failure.
- Blob naming: `Uuid::new_v4().to_string()` — the blob file is written as `<uuid>.blob`. The `blob_name` field in `ChunkRecord` stores only the UUID string (no `.blob` extension); the extension is added when constructing file paths.
- Zeroize: use the `zeroize` crate on the plaintext `Vec<u8>` buffer. The buffer must be zeroized even on the error path — use a guard pattern or explicit cleanup in error branches.
- `proptest` strategy for file sizes: `0usize..=(20 * 1024 * 1024)`. Generate a random byte sequence of that length, write to a `tempfile`, encrypt, decrypt, assert byte equality.
- For the 0-byte file case, `encrypt_file` reads 0 bytes and returns immediately with an empty `Vec<ChunkRecord>`. No staging file is created, no AEAD call is made.
- `decrypt_file` must sort `chunks` by `chunk_index` before processing — do not assume the caller provides them in order.

## Security Review

**Required** — Invoke `security-reviewer` agent after implementation:
- Streaming invariant: confirm no code path accumulates more than one chunk's plaintext in memory
- Zeroization: confirm plaintext buffers are zeroized on both success and error paths
- BLAKE3 pre-decrypt verification: confirm `decrypt_chunk` is never called if the checksum does not match
