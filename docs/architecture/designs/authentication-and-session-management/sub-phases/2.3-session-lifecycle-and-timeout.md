# Phase 2.3: Session Lifecycle and Timeout

**Parent roadmap**: [roadmap.md](roadmap.md)

**Contract anchor**: [Contract Surface](../design.md#contract-surface) in the parent `design.md` is canonical for interface/data/invariant/dependency contracts; keep this sub-phase focused on implementation sequencing and validation.  
**Depends on**: [Phase 2.2](2.2-argon2id-and-session-keys.md) (`SessionKeys` struct)

---

## Deliverables

1. `SessionManager` struct in `src-tauri/src/auth/session.rs` implementing the state machine: `NoSession` → `Active` → `Expired`
2. `authenticate()` method: accepts password bytes plus `Option<&(dyn KeySource + Send + Sync)>` (`None` for Tier 1, `Some(&source)` for Tier 2), `salt`, and `Argon2Params`; runs Argon2id + HKDF (delegating to Phase 2.2); stores `SessionKeys` in the `Active` state. Returns `AuthenticationError` on failure. SQLCipher DB opening is deferred to Phase 3.1 extension of this method.
3. `lock()` method: waits for in-flight operations to complete, drops `SessionKeys`, and transitions state to `Expired`. SQLCipher close is deferred to Phase 3.1; session-lived temp `rclone.conf` overwrite/delete (see [Destination Session Storage](../../../../architecture/designs/cloud-synchronisation/design.md#destination-session-storage)) is deferred to Phase 4.
4. Activity-based timeout: configurable duration (default 15 minutes); stored in local config at `dirs::config_dir()/arx-runa/config.json` (not SQLCipher — must be readable before authentication)
5. `tokio` background timer task: spawned when session enters `Active`; cancelled and restarted on every Tauri IPC command invocation via a `reset_timer()` call
6. Operation-in-progress gate: an atomic counter incremented on operation start and decremented on completion; when the timeout fires, the session manager checks the counter and waits (via `tokio` notify) until it reaches zero before calling `lock()`
7. 60-second pre-warning: the timer task emits `SessionEvent::TimeoutWarning { seconds_remaining }` on an internal broadcast channel 60 seconds before timeout; Phase 6.1 forwards this to Tauri frontend events.
8. Tests:
    - Session transitions from `NoSession` to `Active` on successful `authenticate()`
    - Session transitions to `Expired` when `lock()` is called manually
    - Timeout fires and transitions to `Expired` after the configured duration
    - `reset_timer()` extends the timeout (timer does not fire before the reset deadline)
    - Operation-in-progress counter delays zeroing until the counter reaches zero
    - Re-authentication after `Expired` transitions back to `Active`
    - Key buffers are zeroed after `lock()` (verified via unsafe pointer read in test)

## Validation Checkpoint

**Automated tests**:
```bash
cargo test --workspace auth::session
cargo test --workspace auth::config
cargo clippy --workspace -- -D warnings
```
All tests must pass.

**Manual verification**:
- Set timeout to 5 seconds in local config; authenticate; wait; confirm session expires (`state() == Expired`)
- Confirm the 60-second pre-warning event reaches the frontend (requires Tauri event inspection or log output)

**Security check**:
- After `lock()`, read the raw memory backing `SessionKeys` fields via an unsafe pointer in a test-only function and confirm all bytes are zero
- Confirm the session-lived temp `rclone.conf` cleanup remains explicitly deferred to Phase 4 (TODO hook retained in `lock()`)

**Acceptance criteria**:
- State machine never allows key access from `Expired` state
- Timer reset correctly extends the timeout on each IPC invocation
- Operation-in-progress gate prevents partial-operation zeroing
- Key buffers are demonstrably zeroed (not just dropped) after `lock()`

## Implementation Notes

- Session sharing uses `Arc<RwLock<Option<SessionKeys>>>` (see [`design.md` — Session ownership and sharing](../design.md#session-ownership-and-sharing)). Do not substitute `Mutex` — the `RwLock` allows concurrent reads (file operations) while the write lock is reserved for timeout zeroing and authentication. `SessionManager` wraps this type; Tauri command handlers clone the `Arc` to share it
- Timer cancellation: use a `tokio::sync::watch` channel or `CancellationToken` from `tokio-util` — cancel the previous timer task before spawning a new one on `reset_timer()`
- The operation-in-progress gate uses `tokio::sync::watch::channel<u32>` with `OperationGuard` RAII increment/decrement semantics and a lock/timeout close-gate to prevent post-timeout registrations
- `tokio::time::sleep` is suitable for the background timer in tests; use a short duration (e.g., 100 ms) in tests by injecting the timeout value rather than reading from config
- Do not use `std::thread::sleep` — it blocks the async runtime; use `tokio::time::sleep` throughout
- The local config file for timeout duration uses `dirs::config_dir()` joined with `arx-runa/config.json` across all platforms (Windows, Linux, macOS)
- Per-vault exponential backoff on repeated `InvalidCredentials` is deferred to Phase 2.4/6.1 to keep Phase 2.3 focused on lifecycle and timeout guarantees

---

## Implementation Decisions

- **Operation gate implementation**: used `watch::channel<u32>` plus `OperationGuard` drop decrement and an explicit `operation_gate_closed` flag. **Rationale**: avoids `Notify` registration races and guarantees lock/timeout can block new registrations before waiting for zero. **Deferred follow-up**: Phase 6.1 consumers must bracket command bodies with `begin_operation()`.
- **Timer/event channel shape**: implemented internal `broadcast::Sender<SessionEvent>` with `TimeoutWarning { seconds_remaining: 60 }` and `Locked`. **Rationale**: keeps auth module decoupled from Tauri while preserving warning semantics. **Deferred follow-up**: Phase 6.1 bridges these events to frontend `emit`.
- **Config schema/path**: implemented `{ "schema_version": 1, "session_timeout_secs": u64 }` at `dirs::config_dir()/arx-runa/config.json`, default `900`, clamp `[60, 86400]`. **Rationale**: cross-platform consistency and safe fallback on malformed/missing config. **Deferred follow-up**: none in Phase 2.3.
- **SQLCipher/rclone lifecycle hooks**: retained explicit TODO integration points in `authenticate()` and `lock()` rather than partial stubs. **Rationale**: avoids cross-phase coupling to Phase 3.1/4 deliverables while preserving ordered extension points. **Deferred follow-up**: wire SQLCipher close/open in Phase 3.1 and temp `rclone.conf` cleanup in Phase 4.

## Security Review

**Required** — Invoke `security-reviewer` agent after implementation:
- Timeout correctness: confirm the timer cannot be bypassed by a rapid series of IPC calls that never allow zeroing
- Zeroization on expiry: confirm `zeroize()` is called on the actual key buffer bytes, not on a copy or wrapper that does not own the memory
- Operation-in-progress gate: confirm the gate cannot deadlock (e.g., operation panics without decrementing the counter) — use a `Drop` guard pattern
