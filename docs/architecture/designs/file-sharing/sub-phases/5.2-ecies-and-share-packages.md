## Deliverables

1. ECIES encrypt function in `src-tauri/src/sharing/ecies.rs`:
   - Generate ephemeral X25519 keypair via CSPRNG
   - ECDH between ephemeral private key and recipient's long-term public key → shared secret
   - Derive symmetric key: `HKDF-SHA256(shared_secret, salt=ephemeral_public_key, info="arx-runa-share")`
   - Encrypt payload with XChaCha20-Poly1305 (random 24-byte nonce via CSPRNG)
   - Discard ephemeral private key immediately after ECDH
   - Return wire format: `[32B ephemeral_public_key | 24B nonce | ciphertext | 16B Poly1305 tag]`
2. ECIES decrypt function:
   - ECDH between caller's long-term private key and received ephemeral public key → shared secret
   - Same HKDF derivation as above
   - XChaCha20-Poly1305 decrypt; return error on authentication failure
3. Share package creation in `src-tauri/src/sharing/packages.rs`:
   - Retrieve `file_key` from SQLCipher `nodes` table (unwrap with `key_encryption_key`)
   - Encrypt `file_key` with the ECDH-derived symmetric key (inner wrap, inside the ECIES envelope)
   - Assemble JSON payload: `share_id`, `file_id`, `file_name`, `chunk_count`, `chunk_size`, `chunk_uuids`, `file_key_wrapped`, optional `expires_at`, `cloud_endpoint`
   - Encrypt the entire JSON payload as an ECIES envelope addressed to the recipient's X25519 public key
   - Export the resulting bytes as a `.vgshare` file
4. Share package import:
   - Parse wire format bytes; extract `ephemeral_public_key`, `nonce`, ciphertext
   - Decrypt with caller's X25519 private key via ECIES decrypt
   - Deserialise JSON payload; validate required fields are present (`expires_at` remains optional)
   - Store in `received_shares` table: `share_id`, `sender_contact_id`, `file_name`, `file_key_wrapped`, `chunk_count`, `chunk_size`, `chunk_uuids`, optional `expires_at`, `cloud_endpoint`, `imported_at`
5. Snapshot semantics: `chunk_uuids` is recorded at the moment the share package is created and is never updated; document this as an explicit code comment in the package creation function
6. Test suite covering:
   - ECIES round-trip: encrypt with recipient public key, decrypt with recipient private key, recover original plaintext
   - Wrong-recipient rejection: decrypt with a different private key produces an authentication error
   - Corrupted ciphertext (single-byte flip in ciphertext body) is rejected by Poly1305 authentication
   - MITM-substituted ephemeral public key: attacker replaces the 32-byte ephemeral key; decryption with correct private key fails (wrong HKDF input)
   - Share package JSON schema validation: missing required field (other than optional `expires_at`) produces an import error
   - Share package expiration continuity: `expires_at` may be omitted or `null`; when present, it round-trips into `received_shares` unchanged
   - Share package import → received_shares row contains correct field values

## Validation Checkpoint

**Automated tests**:
```bash
cargo test sharing::ecies
cargo test sharing::packages
```
All tests must pass with no warnings.

**Manual verification**:
- Create a share package for a test file; inspect the raw bytes — first 32 bytes are the ephemeral public key, bytes 32-55 are the nonce
- Import the package on the same Arx Runa instance (using own public key as the recipient); verify a row appears in `received_shares`

**Acceptance criteria**:
- ECIES decrypt returns a distinct authentication error on any modification to ephemeral key, nonce, ciphertext, or tag
- Ephemeral private key is not retained in any struct field, static variable, or log output after the ECDH step
- `file_key_wrapped` in the share package is distinct ciphertext from the `file_key_wrapped` stored in the `nodes` table (different encryption key and nonce)
- Snapshot semantics are enforced: `chunk_uuids` in the package matches the file's chunks at creation time; no live pointer to the current state of the file

## Implementation Notes

- Use `x25519_dalek::EphemeralSecret` (not `StaticSecret`) for the ephemeral keypair — the `EphemeralSecret` type is consumed by the ECDH operation and cannot be retained, enforcing the disposal requirement by the type system
- HKDF salt must be the 32-byte ephemeral public key bytes (not a zero-length salt); this matches the `age` tool construction referenced in the design
- `file_key_wrapped` in the JSON uses standard base64 encoding (the bytes are not human-readable; base64 keeps the JSON valid)
- The outer ECIES envelope encrypts the entire JSON string as bytes; the inner `file_key_wrapped` field is an additional encryption layer inside the decrypted JSON — both layers use the same ECDH-derived symmetric key but different nonces
- Wire format parsing: read exactly 32 bytes for `ephemeral_public_key`, exactly 24 bytes for `nonce`, remaining bytes minus 16 for ciphertext, final 16 bytes for Poly1305 tag; return a parse error if the total length is less than 72 bytes
- `received_shares.file_key_wrapped` stores the inner `file_key_wrapped` blob as retrieved from the decrypted JSON; decryption of the `file_key` itself happens at file access time, not at import time
- `expires_at` is an optional Unix timestamp; when Phase 6 `share_file(expiration_days)` provides a value, compute and include it in the package, otherwise omit it or set it to `null`

## Security Review

**Required** — Invoke `security-reviewer` agent after implementation:
- ECIES correctness: ephemeral key disposal (enforced by `EphemeralSecret` type), HKDF salt set to `ephemeral_public_key`, nonces generated via CSPRNG
- No `file_key` plaintext appears in log output, error messages, or the exported `.vgshare` file in unwrapped form
- Authentication tag covers the full ciphertext; partial-payload attacks are rejected
