## Deliverables

1. `LoginPage` component in `src/auth/login_page.rs`: password `<input type="password">`, `KeyFileIndicator` sub-component, error display, submit button that calls `authenticate` IPC, password string zeroed via `zeroize` immediately after the IPC call completes
2. `KeyFileIndicator` component: auto-detects key file path from `DeviceMonitor` events and displays the detected path; falls back to a manual file selection button when no device is detected
3. `VaultBrowser` component in `src/vault/vault_browser.rs`: `Breadcrumbs`, `FileList`, `UploadButton`, loading spinner, and error display; reads state from `use_session()` and `use_vault_actions()`
4. `FileList` component rendering a list of `FileItem` entries; each `FileItem` shows type icon, name, size, and modified date
5. `Breadcrumbs` component rendering the `current_path` as clickable path segments, each calling `VaultActions::navigate`
6. `UploadButton` component triggering a native file picker and calling the `upload_file` IPC command
7. `ProgressModal` component in `src/transfer/progress_modal.rs` displaying real-time transfer progress from `tauri::ipc::Channel<ProgressUpdate>`; shows bytes transferred, total bytes, and a progress bar
8. `AppShell` layout component in `src/layout/app_shell.rs`: header with application logo and `SessionStatus` display
9. `SessionStatus` component: shows remaining session timeout countdown and a lock button that calls `lock_session` IPC then `VaultActions::clear()`
10. Generic components in `src/components/`: `Button`, `Input`, `Modal`, `Spinner`
11. Leptos routing in `src/main.rs`: renders `LoginPage` when `SessionState.is_unlocked` is false, renders `VaultBrowser` wrapped in `AppShell` when true
12. Tailwind CSS styling with dark mode palette (`bg-void-950` and related custom tokens defined in `tailwind.config.js`)

## Validation Checkpoint

**Automated tests**:
```bash
trunk build
```

Component tests (where Leptos testing infrastructure supports):
- `Breadcrumbs` renders one segment per path component
- `SessionStatus` lock button triggers `VaultActions::clear()` and navigates to login view

**Manual verification**:
- Open the application, enter credentials and a key file, verify navigation to `VaultBrowser`
- Navigate into a directory via `Breadcrumbs`; verify `FileList` updates and path segment is added
- Initiate an upload; verify `ProgressModal` appears and updates in real time
- Click the lock button in `SessionStatus`; verify the UI returns to `LoginPage` and no file data is visible

**Acceptance criteria**:
- `trunk build` completes without errors
- The login → vault browser navigation flow works end to end with a running backend
- `ProgressModal` receives and renders at least one `ProgressUpdate` event during an upload

## Implementation Notes

- The password `zeroize` call must happen inside the `authenticate` handler regardless of whether the IPC call succeeds or fails — use a `defer`-style pattern or explicit cleanup on both branches
- `tauri::ipc::Channel<ProgressUpdate>` is passed from the frontend as an IPC argument; the channel is created in the WASM layer via the Tauri JS API before calling `invoke_command`
- Tailwind custom colours (e.g., `bg-void-950`) require a `tailwind.config.js` `extend.colors` entry; define the full palette here rather than scattering ad hoc hex values across components
- `DeviceMonitor` events for `KeyFileIndicator` arrive as Tauri events (not commands); use `tauri::event::listen` in the WASM layer to subscribe
- `Modal` component should render into a portal at the document root to avoid z-index conflicts with the `AppShell` layout
