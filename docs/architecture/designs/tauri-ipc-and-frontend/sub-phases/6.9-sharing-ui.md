# Phase 6.9: Sharing UI

**Parent roadmap**: [roadmap.md](roadmap.md)  
**Design sections**: [Canonical Command Surface (Normative)](../design.md#canonical-command-surface-normative), [Command Signatures](../design.md#command-signatures), [Vault Browser](../design.md#vault-browser), and [Zero-Trace Compliance](../design.md#zero-trace-compliance) of [design.md](../design.md)  
**Contract anchor**: [Contract Surface](../design.md#contract-surface) in the parent `design.md` is canonical for command/type contracts; keep this sub-phase focused on sharing workflow UI.  
**Depends on**: [Phase 6.8](6.8-vault-settings-ui.md) (vault settings surface complete)

This phase delivers the full sharing UI surface: contact management, per-file share action, and sent/received share panels. All cryptographic operations remain in the Phase 5 backend; the frontend is limited to collecting user intent and displaying results.

---

## Deliverables

1. `/contacts` route added to the `Router` in `src/app.rs`
2. New file `src/contacts.rs` with:
   - `ContactList` component: calls `list_contacts` on mount, renders one `ContactItem` per entry (name, public key fingerprint — last 8 hex chars of the key hash)
   - `AddContactForm` component: name field + public key paste field (multi-line `<textarea>`); validates non-empty before submitting; calls `add_contact { name, public_key_pem }` via `invoke_command`; on success refreshes contact list
   - `ExportKeyButton` component: calls `export_public_key` via `invoke_command`; renders result in a `Modal` with a copy-to-clipboard button (using `navigator.clipboard.writeText`); key string cleared from signal when modal is dismissed
3. Person icon navigation link to `/contacts` in `AppShell` header
4. `/shares` route added to the `Router` in `src/app.rs`
5. New file `src/shares.rs` with:
   - `SharesPage` component with two tabs: **Sent** and **Received**
   - `SentSharesList` component: calls `list_shares` on mount, renders one `SentShareItem` per entry (file name, recipient name, optional expiry date, revoke button)
   - `SentShareItem` revoke button: calls `revoke_share { share_id }` via `invoke_command` after a `Modal` confirmation ("Revoke access for `<recipient>`?"); on success refreshes the sent list
   - `ReceivedSharesList` component: calls `list_received_shares` on mount, renders one `ReceivedShareItem` per entry (file name, sender name, optional expiry date, import button)
   - `ReceivedShareItem` import button: calls `import_share { share_id }` via `invoke_command`; on success calls `vault_actions.navigate(current_path)` to refresh the vault listing
6. Share icon navigation link to `/shares` in `AppShell` header
7. Share action button added to each `FileItem` (non-directory entries only) in `src/vault.rs`:
   - Click opens `ShareModal`
   - `ShareModal` component: contact picker (fetches `list_contacts` on open and renders as a dropdown), optional expiry date picker (`<input type="date">`), optional receipt checkbox
   - Confirm calls `share_file { file_id, contact_id, expires_at, request_receipt }` via `invoke_command`
   - On success: inline "Shared with `<contact name>`" confirmation, modal closes
8. `AddContactRequest`, `ShareFileRequest`, `RevokeShareRequest`, `ImportShareRequest` structs in `src/ipc_types/requests.rs`
9. `ContactEntry`, `ShareEntry`, `ReceivedShareEntry` response types re-exported from `src/ipc_types/` (mirroring `src-tauri/src/ui/types.rs`)
10. `contacts` and `shares` modules re-exported from `src/lib.rs`

## Validation Checkpoint

**Automated tests**:
```bash
trunk build
cargo test --workspace
```

- `share_modal_disables_submit_with_no_contact_selected` unit test: verify the Share button is disabled when no contact is chosen
- `received_share_item_import_refreshes_vault` unit test (mock IPC): verify `vault_actions.navigate` is called after a successful import

**Manual verification**:
- Navigate to `/contacts`; verify contact list loads and a new contact can be added
- Click "Export my public key"; verify the key appears in a modal; close modal; verify key is no longer in any visible state
- Navigate to the vault browser; click the share icon on a file; verify `ShareModal` opens with the contact list populated
- Select a contact, optionally set expiry, and confirm; verify "Shared with X" confirmation appears
- Navigate to `/shares` → Sent tab; verify the new share entry appears with a revoke button
- Revoke the share; verify it disappears from the list
- Switch to Received tab; verify any incoming shares are listed with an import button
- Import a received share; verify the file appears in the vault browser

**Acceptance criteria**:
- `trunk build` completes without errors
- Exported public key string is cleared from all signals after the modal is dismissed
- No contact public key data is logged, stored in localStorage, or held in a context signal
- Vault listing refreshes automatically after importing a received share
- Revoking a share requires a confirmation step — no single-click revocation

## Implementation Notes

- Public key display: show only the last 8 hex characters of a BLAKE3 hash of the raw key bytes as the "fingerprint" — the full key is available on hover or via the export modal; never display the full key inline in lists (UI noise and accidental disclosure risk)
- `ExportKeyButton` modal: revoke the `navigator.clipboard.writeText` result promise; do not surface clipboard errors to the user (fail silently with a console note, not an alert)
- `ShareModal` contact picker: use a `LocalResource` (not an `Effect`) to fetch `list_contacts` when the modal opens; close + reopen must re-fetch to pick up newly added contacts
- `expires_at` field: format as an ISO 8601 date string (`YYYY-MM-DD`) from the `<input type="date">` value; send `None` if the field is empty
- Import button should be disabled while the import call is in flight to prevent double-import

## Security Review

**Not required** — all sharing cryptography (HPKE key wrapping, share package creation, revocation key rotation) is implemented in the Phase 5 backend. The frontend passes opaque identifiers (`file_id`, `contact_id`, `share_id`) and displays names/fingerprints. The one sensitivity touchpoint — the exported public key — is ephemeral in the modal and cleared on dismiss; no new Zero-Trace properties are introduced beyond what Phase 6.4 established.
