## Deliverables

1. Create `Trunk.toml` at the project root using the **Trunk Configuration** section of [`design.md`](../design.md#trunk-configuration). Copy the `[build]` and `[[hooks]]` blocks directly from there. The hook uses `@tailwindcss/cli` (Tailwind v4 — the CLI is a separate package).

2. Create `index.html` as Trunk's entry point (if not generated by the template):
   ```html
   <!DOCTYPE html>
   <html lang="en">
     <head>
       <meta charset="UTF-8" />
       <meta name="viewport" content="width=device-width, initial-scale=1.0" />
       <title>Arx Runa</title>
       <link data-trunk rel="css" href="output.css" />
       <link data-trunk rel="rust" />
     </head>
     <body></body>
   </html>
   ```

3. Create `input.css` using the **Tailwind Integration** section of [`design.md`](../design.md#tailwind-integration). Copy the `@import "tailwindcss"` import and the full `@theme {}` block directly from there. Tailwind v4 auto-detects source files — no `content` configuration required.

4. Delete `tailwind.config.js` if generated by the template. Tailwind v4 has no JS config file — the entire theme lives in `input.css`.

5. Create `package.json` if not already present (Tailwind v4 requires two packages — see the note in the [Trunk Configuration section of `design.md`](../design.md#trunk-configuration)):
   ```json
   { "devDependencies": { "tailwindcss": "^4", "@tailwindcss/cli": "^4" } }
   ```
   Run `npm install`. Add `node_modules/` to `.gitignore` if not already present.

6. Verify the complete acceptance criteria from the design document:
   - `cargo fmt --all -- --check` passes
   - `cargo clippy --all-targets --all-features -- -D warnings` passes
   - `cargo test --all-targets` passes
   - `cargo build --release` succeeds
   - `cargo tauri dev` launches a window showing the Leptos app (manual)

7. Update `docs/guides/development.md` with Tauri-specific build and run instructions covering:
   - Prerequisites: Rust, Node.js, Trunk (`cargo install trunk`), Tauri CLI (`cargo install tauri-cli`)
   - Dev workflow: `cargo tauri dev`
   - Production build: `cargo tauri build`
   - Running only the frontend: `trunk serve`
   - Running only backend tests: `cargo test -p arx-runa-tauri`

8. Mark Phase 0 as complete in `docs/roadmap.md` (change `Status: Planned` to `Status: Complete`)

## Validation Checkpoint

**Automated**:
```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets
cargo build --release
```
All four must pass.

**Manual verification**:
- Run `cargo tauri dev` — a desktop window must open showing the default Leptos content
- Inspect the Trunk output in `dist/` — `output.css` must exist and contain compiled Tailwind classes
- Check that brand token classes (`bg-iron`, `text-bone`, `text-rune`, `border-steel`) appear in `output.css`

**Acceptance criteria**:
- All four `cargo` commands above exit 0
- `cargo tauri dev` opens a window (smoke test — content can be the Leptos default)
- Tailwind brand token classes (iron, stone, steel, rune, bone palette) are present in the compiled CSS
- `docs/guides/development.md` has been updated with Tauri instructions
- `node_modules/` is in `.gitignore`

## Implementation Notes

- The Tauri template may already generate `index.html`. If so, check that it has the `data-trunk rel="rust"` link tag and that the CSS link points to `output.css`. Modify rather than replace if the template version differs.
- `trunk serve` and `cargo tauri dev` both need to be running for full hot-reload. Tauri's `beforeDevCommand = "trunk serve"` handles this automatically — Tauri starts Trunk as a child process.
- Tailwind v4 has no `tailwind.config.js`. Delete any such file the template generates — the entire theme is defined in `input.css` via `@theme {}`.
- Tailwind v4 auto-detects source files — no `content` paths needed. If compiled `output.css` is missing expected classes, confirm `input.css` is being processed by the Trunk hook.
- `node_modules/` can be large (~50 MB). Confirm it is excluded from the repo via `.gitignore` before committing.
- The `docs/guides/development.md` update should reference exact commands, not generic descriptions. Future contributors should be able to clone and run with zero prior knowledge of Tauri.
