## Deliverables

1. SQLCipher schema creation in `src-tauri/src/storage/schema.rs` using the canonical table/constraint definitions from [Manifest Database Schema](../design.md#manifest-database-schema), including manifest metadata seed keys and validation hooks for `chunk_size_bytes` and `epoch_buffer_enabled`.
2. Future-phase tables created in the same schema (no runtime logic yet): `destination_sessions` (Phase 4 multi-destination metadata), plus sharing tables `contacts`, `shares`, `received_shares` (Phase 5) — see [Manifest Database Schema](../design.md#manifest-database-schema)
3. `Node` struct in `src-tauri/src/storage/mod.rs` with fields matching the `nodes` table; `ChunkRecord` struct with fields matching the `chunks` table (`chunk_id`, `chunk_index`, `blob_name`, `size_padded`, `blake3_checksum`) — no `blob_path` field; the staging path is derived at the call site as `staging_directory/<blob_name>.blob`
4. `StorageError` thiserror enum covering: `Database`, `NotFound`, `ChecksumMismatch`, `Io`, `WrongKey`, `ConstraintViolation`
5. `MetadataStore` trait in `src-tauri/src/storage/mod.rs` with `#[async_trait]`, aligned with [MetadataStore Trait](../design.md#metadatastore-trait) for canonical method signatures
6. `SqlCipherMetadataStore` implementation in `src-tauri/src/storage/sqlcipher.rs` backed by `rusqlite` with SQLCipher; all mutations wrapped in transactions
7. `MockMetadataStore` implementation in `src-tauri/src/storage/mock.rs` using in-memory `HashMap` for testing without a database
8. Test suite covering: SQLCipher wrong-key rejection, CASCADE deletion (delete node → chunk rows deleted), `UNIQUE(node_id, chunk_index)` constraint enforcement, insert/get round-trip for both `Node` and `ChunkRecord`, `list_children` returns correct subset, 0-byte file (node with no chunks inserts and retrieves without error)

## Validation Checkpoint

**Automated tests**:
```bash
cargo test storage::metadata
```
All tests must pass.

**Manual verification**:
- Open the manifest SQLite file with a standard SQLite browser (without providing `sqlcipher_key`) — confirm the file is unreadable (binary gibberish, not a valid SQLite header)
- Open with the correct key — confirm all tables and seed rows are present

**Acceptance criteria**:
- All `MetadataStore` trait methods defined in the parent design have working implementations in both `SqlCipherMetadataStore` and `MockMetadataStore`
- Wrong-key rejection returns `StorageError::WrongKey`, not a panic or silent corruption
- Deleting a node cascades to its chunk rows; blob names are returned to the caller
- `increment_snapshot_counter` is atomic within a transaction

## Implementation Notes

- Apply `PRAGMA key = '...'` immediately after opening the SQLCipher connection, before any other statement. Any schema or data access before `PRAGMA key` opens the file unencrypted.
- The `sqlcipher_key` is a 32-byte raw key from `SessionKeys`. Use `PRAGMA key = "x'<hex>'"` syntax for raw binary keys rather than passphrase derivation — SQLCipher's internal KDF is bypassed this way (Argon2id has already been applied in Phase 2).
- `file_key_wrapped` is `NULL` for directory nodes and `NOT NULL` for file nodes. This is enforced by a cross-column SQL `CHECK` constraint in the schema — any `INSERT` that violates the invariant will fail with `CHECK constraint failed`. The application layer (`insert_node`) should still validate this before the INSERT for a cleaner error message, but the database is the authoritative guard.
- `MockMetadataStore` must use `Arc<Mutex<...>>` for interior mutability to satisfy `Send + Sync` bounds on the trait.
- `destination_sessions` is created in this schema phase for continuity with Phase 4; destination runtime logic is implemented in Phase 4, not here.
- Sharing tables (`contacts`, `shares`, `received_shares`) are also created in the schema migration but no trait methods or application logic are added until Phase 5. Include comments in the schema file marking these phase boundaries.

### Implementation Notes addendum

- Trait and domain type placement follows the Rust structure rule: `MetadataStore` lives in `src-tauri/src/storage/metadata_store.rs`, `Node` and `ChunkRecord` live under `src-tauri/src/storage/types/`, and `src-tauri/src/storage/mod.rs` is re-exports only.
- Wrong-key detection uses a sentinel read (`SELECT count(*) FROM sqlite_master`) after SQLCipher key application; `SQLITE_NOTADB` maps to `StorageError::WrongKey`.
- `vault_identity` remains present as an ancillary table appended after the canonical schema so existing auth ceremonies remain compatible during Phase 3.1.

## Implementation Decisions

- Kept `MetadataStore` trait signatures UUID-based for Phase 3.1 (rationale: preserve canonical contract surface and avoid broad API churn in this sub-phase); deferred follow-up: evaluate `NodeId` boundary migration in a later scoped phase.
- Enforced subtree-safe delete semantics in both SQLCipher and mock stores (rationale: satisfy invariant §10 by queuing all descendant blob names into `pending_deletions` before cascading delete commit).
- Added immutable `manifest_meta` write guards and stricter open-time metadata/schema validation (rationale: prevent silent drift of vault-critical invariants such as `chunk_size_bytes` and `epoch_buffer_enabled`).
- Deferred broader auth rotation cloud-consistency work (manifest-backup rotation and final ceremony commit semantics) to a later phase (rationale: outside Phase 3.1 storage-schema closure scope).
